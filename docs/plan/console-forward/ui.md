# 控制台转发：交互与状态（v1）

> 状态：设计已确认；T4 侧边双模式未实施。
> 上游：[README.md](./README.md)。接口：[api.md](./api.md)。落地计划：[implementation.md](./implementation.md)。

## 1. 目标交互

侧边对话栏在现有「独立对话」之外增加「转发」模式。用户当前选中某个轨迹会话，侧边栏能显示该会话对应的 pi TUI 控制台状态；切到转发后，输入的问题直接进入该控制台，由控制台执行。

```text
┌ 轨迹观察 ─────────────────────────────────────────────── [主题] [对话] ┐
│ π │ 会话                 │ 轨迹主区                         │ 对话          │
│   │ ● 会话 A  ▣ 运行中   │                                  │ [独立] [转发] │
│   │ ○ 会话 B             │  第 1 轮  ▾                      │               │
│   │                      │   [x] 提问  帮我改…              │ ▣ 控制台运行中 │
│   │                      │   [x] 工具  bash …               │   PID 12345   │
│   │                      │   [ ] 回答  已完成               │               │
│   │                      │                                  │ 你 → 控制台    │
│   │                      │                                  │ 已排队         │
│   │                      │                                  │               │
│   │                      │                                  │ ┌───────────┐ │
│   │                      │                                  │ │ 转发问题…  │ │
│   │                      │                                  │ └───────────┘ │
│   │                      │                                  │ [排队▾] [↑]  │
└─────────────────────────────────────────────────────────────────────────┘
```

- 模式切换常驻输入卡左侧，不新增顶部对话头。
- 控制台状态是独立状态条，不与 `live` 混用。
- 转发模式下，侧边不出现独立对话的 AI 气泡、工具卡片、审批弹层。

## 3. 模式切换

### 3.1 默认与记忆

- 默认：**独立**。
- 按 `source:sessionId` 记忆到 `localStorage["tw.chatMode"]`：
  ```json
  { "pi:20261110T090000-abc": "forward" }
  ```
- 未记录 → 独立。
- 切换会话时恢复该会话的模式；没有记录时独立。
- 页面刷新后恢复；如果记录的是转发但控制台已不在，进入「转发不可用 / 已离线」状态，不自动降级为独立，避免用户误以为问题发到了别处。

### 3.2 可点条件

| 条件 | 转发按钮 |
| --- | --- |
| 当前会话有且仅有一个有效注册控制台 | 可点 |
| 控制台 `idle` / `working` | 可点 |
| 控制台心跳过期 / 桥不可达 | 不可点，显示「控制台已离线」 |
| 当前会话没有注册 | 不可点，显示「未检测到可转发控制台」 |
| 同一会话多个注册 | 不可点，显示「检测到多个控制台」 |
| source 不是 pi | 隐藏或禁用，显示「仅 pi 支持转发」 |
| 当前独立对话有活动 turn | 可切换，但发送禁用，提示先停止独立对话 |

- 禁用时使用 `disabled` + `aria-disabled`，不要只做置灰。
- 点击禁用按钮时给一个轻提示/说明，不弹「连接」对话框。

### 3.3 老控制台

没有注册时统一显示：

```text
未检测到可转发控制台
该会话的控制台可能未加载 pi-chat-helper，或在插件安装前已启动。
空闲时可在控制台执行 /reload，或重启 pi 后刷新本页。
```

- `/reload` 只在扩展位于可热加载的自动发现位置时可靠；通过 `pi install` 安装后，重启最稳。
- 不显示「连接控制台」按钮。
- 不在页面调用 herdr/tmux/send-keys。
- 不把 `live` 当作「有控制台」；可以在提示里写「文件仍在活跃」。

## 4. 控制台状态

### 4.1 状态条

| 状态 | 文案 | 视觉 | 行为 |
| --- | --- | --- | --- |
| `working` | 控制台运行中 | 实心点 + 警示/进行色 | 默认排队；可显式插话 |
| `idle` | 控制台在线空闲 | 空心点 + 正常色 | 发送后立即开始 |
| `offline` | 控制台已离线 | 灰色点 | 禁用输入/发送；保留草稿 |
| `none` | 未检测到可转发控制台 | 无点/问号 | 禁用转发；显示说明 |
| `ambiguous` | 检测到多个控制台 | 警示点 | 禁用转发；提示去控制台确认 |
| `unsupported` | 仅 pi 支持转发 | 灰色点 | 禁用 |

- 状态条 `aria-live="polite"`，状态变化时播报一次，不每次轮询重复播报。
- 文案中的 PID 仅用于识别，不作为安全依据。
- 如果控制台切到别的会话：状态变为 `none` 或 `offline`，并显示「控制台当前不在该会话」。

### 4.2 会话列表徽标

- 保留现有 `live-dot`。
- 新增 `console-badge`：
  - `working`：运行中标记；
  - `idle`：在线标记；
  - 没有注册：不渲染。
- `live` 与 console badge 是两个元素、两个 `title`，不能合并。
- 徽标有文本/`aria-label`，不要只靠颜色区分。

## 5. 转发模式的消息区

### 5.1 显示内容

转发模式不混入独立线程消息，显示本会话的**转发记录**：

```text
你 → 控制台
帮我跑一下测试

已排队：控制台正在执行当前任务，完成后处理。
```

条目类型：

| 类型 | 内容 |
| --- | --- |
| `forward-user` | 用户问题、时间、目标控制台 PID |
| `forward-status` | 已开始 / 已排队 / 已插话 |
| `forward-error` | 无控制台 / 离线 / 会话不匹配 / 多控制台 / 超时 |
| `forward-offline` | 控制台断开、切走 |

- 不渲染假的 assistant 回答。
- 不渲染侧边工具卡片、审批卡片。
- 顶部固定说明：
  ```text
  转发模式：回答和工具审批在控制台完成；主轨迹区会显示新事件。
  ```
- 空态：
  ```text
  输入问题，转发到当前控制台。
  ```
- 转发记录只保存在当前页面内存；刷新后清空；不写 `turns.jsonl`，不创建独立 pi 线程。
- 独立线程消息不删除；切回独立时恢复显示。

### 5.2 发送结果

| 结果 | 行为 |
| --- | --- |
| `now` | 清空输入；显示「已发送，控制台开始执行」 |
| `followUp` | 清空输入；显示「已排队，控制台完成当前任务后处理」 |
| `steer` | 清空输入；显示「已插话，控制台会在当前工具结果后处理」 |
| 错误 | 保留输入；按 code 显示具体原因 |

- 不因为发送成功就假设控制台会执行成功；后续工具失败/审批拒绝在控制台和主轨迹区显示。
- 控制台状态在发送后立即乐观更新为 `working`；下一次轮询校准。

## 6. 忙碌：排队 / 插话

- 控制台 `working` 时，输入卡右侧出现一个小选择器：

```text
[排队（推荐）▾] [↑]
```

- 选项：
  - **排队（默认）**：`followUp`，当前任务结束后处理；
  - **插话**：`steer`，在当前工具结果后介入；第一次选择时确认：
    ```text
    插话会改变控制台当前任务的方向，确定发送？
    ```
- 控制台 `idle` 时隐藏选择器，直接发送。
- 状态可能过期；以服务端返回的实际 `delivery` 为准，并显示对应文案。
- 「插话」不叫「中断」：它不保证立即停止当前工具，也不等于 Ctrl+C。

## 7. 离线、切会话与断连

### 7.1 控制台离线

- 状态条变「控制台已离线」；输入和发送禁用；保留草稿。
- 如果正在发送时断连：请求失败，输入保留；显示「控制台已离线，问题未发送」。
- 提供「切回独立」按钮；不自动发送、不自动切换。

### 7.2 控制台切到别的会话

- 当前会话不再匹配：转发不可用；显示「控制台当前在另一个会话」。
- 不自动把控制台切回该会话。
- 用户可以在控制台切回，或使用独立模式。

### 7.3 控制台退出

- 注册消失；状态 `offline`/`none`；转发禁用。
- 已发送的排队消息状态未知；侧边不假装成功；提示去控制台确认。

## 8. 独立模式不回归

- 现有独立对话的消息、工具卡片、审批、模型/技能/profile/上下文、`/new`、`/resume` 全部保持。
- 模式切换到转发时，不停止独立 child；切回时恢复线程。
- 独立对话正在流式时：
  - 可以切到转发查看状态；
  - 转发发送禁用，提示「独立对话正在运行，先停止或等待完成」，避免并发修改工作区。
- 独立模式下如果同一会话控制台正在工作：
  - 显示一条轻提示「该会话的控制台正在运行，独立对话可能与其并发修改工作区」；
  - 不强制阻止，独立模式本来就是隔离路径。

## 9. 键盘与可访问性

- 模式切换：两个 `button`，`role="tab"` 或 `aria-pressed`；左右方向键可切换；焦点不丢。
- 状态条：`aria-live="polite"`；状态变化只播报一次。
- 发送：Enter 发送（非 IME 组合中）；Shift+Enter 换行；与独立模式一致。
- 转发模式下 `/` 不打开命令面板，作为普通字符发送；`+`、模型、技能、profile、上下文控件隐藏或禁用。
- 所有禁用按钮有 `title` / `aria-describedby` 说明原因。
- 队列/插话选择器有明确 label；不能用颜色单独表示状态。
- 转发记录作为 `role="log"` 的内容追加；不要每轮重建整段 DOM 导致读屏重复。

## 10. 边界与空态

| 场景 | UI |
| --- | --- |
| 没有选会话 | 转发不可用；提示先选会话 |
| 选的是 Codex 会话 | 转发隐藏/禁用；提示仅 pi 支持 |
| 当前会话无注册 | 「未检测到可转发控制台」+ 重启/`/reload` 说明 |
| 有注册但心跳过期 | 「控制台已离线」+ 切回独立 |
| 多控制台 | 「检测到多个控制台」+ 禁用转发 |
| 控制台在别的会话 | 「控制台当前在另一个会话」+ 禁用 |
| 独立 turn 正在跑 | 转发发送禁用；提示先停止 |
| 转发中抽屉关闭 | 请求继续；重新打开时按当前状态恢复 |
| 页面刷新 | 模式恢复；转发记录清空；状态重新拉取 |

## 11. 验收交互

1. 侧边出现 `[独立] [转发]`；默认独立。
2. 有精确在线控制台时会话列表出现 console badge；侧边状态为运行中/空闲。
3. 转发空闲：发送后控制台出现用户消息；侧边显示「已发送」。
4. 转发忙碌：默认排队；选择插话需确认；实际 delivery 回显正确。
5. 无控制台：转发禁用；文案为「未检测到可转发控制台」，没有「连接」按钮。
6. 控制台退出/切会话：转发立即禁用；草稿保留；可切回独立。
7. 独立模式的消息、审批、模型、技能、上下文、`/new`、`/resume` 不回归。
8. `/` 在转发模式不打开命令面板；模型/技能/profile/上下文控件不可用。
9. 页面刷新后模式恢复；离线态清楚；不出现假的成功状态。
